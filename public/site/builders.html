Model Context Protocol

One command turns your business into AI tools

Shuug ships a real MCP server. Any MCP client — Claude, your own agent — connects over stdio and gets typed, guarded tools for the whole operation. Every tool is annotated read-only vs destructive vs idempotent and runs through the same guarded transition engine as the app, so an agent can't do anything a person couldn't.

your terminal
# 1. mint a workspace token for this backend
npm run backend:setup

# 2. start the shuug-business MCP server (stdio)
npm run mcp

# then add it to your MCP client (Claude, an agent, an IDE)…
# the model now has typed, guarded tools for the whole business.
A few of the tools

Typed tools, real guardrails

invoice_command write

Issue a reviewed, itemized invoice — parties, prices, tax, terms — posted atomically to the ledger.

journal_command write

Record a balanced manual journal or dated reversal, integer cents, requestId-safe on retry.

business_read read

Read any part of the workspace — customers, orders, balances, revisions — before acting.

schedule_command write

Build shifts and staff schedules that feed timesheets, job cost and payroll.

tracker_create write

Spin up a brand-new no-code tool/tracker on the fly — fields, records, the works.

capabilities read

Ask the core what it can do right now — the capability surface every app is a view of.

Bring your own model

Point it at your model and hook it up

No bundled AI, no per-token bill, no vendor lock. Run fully local with Ollama, or use Claude — it's one env change. That's the whole "AI setup": point Shuug at a model and it's wired.

.env · fully local
# runs offline — nothing leaves your box
COPILOT_PROVIDER=ollama
OLLAMA_HOST=http://localhost:11434
OLLAMA_MODEL=gemma3:4b
.env · Claude
# or point it at a hosted model
COPILOT_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-…
COPILOT_MODEL=<your-model>

Built for agentic development

Don't ask AI to rebuild the boring parts.

Shuug already contains the business primitives. Your agent retrieves and composes existing modules first, modifies them when necessary, and builds new functionality only when it genuinely doesn't exist. That's the difference between a codebase an agent can hack on and one it can actually build with.

❌ the spaghetti loop
request → generate another feature
        → more code → spaghetti
✅ the Shuug loop
request → find capability
        → compose → minimal modification
🔎 Retrieve before generating

The agent finds an existing capability before writing anything new — the whole business surface is queryable.

🧩 Compose before creating

It assembles modules that already exist instead of reinventing them, so you don't grow a second, worse copy of the app.

✂️ Modify the smallest surface

When change is genuinely needed, it touches the least code possible — guarded transitions keep the blast radius small.
